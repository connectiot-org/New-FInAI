# FinAI Assistant operator runbook

Implementation date: 25 October 2026 (Asia/Dhaka). Read RELEASE.md and WORKSPACE.md first. This is an additive session-authenticated feature, not deployment approval.

## Configuration and privacy

Keep ASSISTANT_ENABLED=false until the release gates below are satisfied. Supply secrets through secure server settings only; never VITE variables, browser storage, source, logs or chat. Required server settings: OPENROUTER_API_KEY, ASSISTANT_ENABLED=true, ASSISTANT_MODEL (explicit exact model ID), ASSISTANT_OPENROUTER_PROVIDERS (approved comma-separated provider names), ASSISTANT_DAILY_TOKEN_LIMIT (integer 50000–100000000), ASSISTANT_MAX_INPUT_PRICE and ASSISTANT_MAX_OUTPUT_PRICE (USD per million tokens, both explicitly0 under the requested free-only policy). No model/provider/budget defaults are selected. Set a separate provider-account spend cap and assign a billing owner; token reservation is not a dollar billing reconciliation.

The adapter makes two non-streamed structured-output calls to https://openrouter.ai/api/v1/chat/completions, with only approved providers, no routing fallback, required parameter support, data_collection=deny and zdr=true. Response model and provider must match configuration. This deliberately fails if the provider cannot meet those requirements. Verify current official API semantics and selected model support before enabling: documentation access was blocked in this environment. Obtain processor/data-transfer approval before sending customer questions, preferences, bounded history and authorized fact labels. No claim that account-level retention or processor contracts have been independently verified.

Each call has a 12-second deadline, 16000-byte input bound, 32768-byte response bound and 1000 output-token cap. No arbitrary model SQL, URL fetching or financial writes. The model plans bounded reads and selects server fact IDs; financial arithmetic and mandatory caveats stay server-owned. Answer detail is supported; translation and tone guarantees are not.

## Persistence, concurrency and retention

Deploy migrations normally with npm run db:migrate (seven total migrations, including 202610250001_assistant and 202610250002_assistant_deletion_receipts); never reset/seed a target. Back up first and verify readiness after deployment. New tables contain conversations, turns, preferences, daily reservation counters, immutable ledger snapshots and UUID-only deletion receipts. Existing demo storage and application records are preserved.

Conversations expire after 30 days, preferences 365 days after explicit save/edit, deletion receipts after 90 days, and old daily counters after 90 days. Expired records are inaccessible before physical cleanup. Run node --env-file=.env --import tsx scripts/cleanup.mts first as a dry run; append --apply only in an approved operator runtime. Schedule it and repeat until the bounded batches (100 conversations/preferences/leases per run) drain. The target scheduler/owner is not configured here. Business sources and audit records are never removed by this cleanup.

A conversation has at most 200 turns and one pending turn; at most two turns per organisation run concurrently. Each accepted turn reserves 50000 daily tokens durably without refund, including cancellation/failure, so retries cannot reclaim spend. A stable turn UUID replays its original outcome; changed payload conflicts. Forty-second leases fail abandoned work rather than rerunning the provider. Cancel/delete/revoke block late publication; local abort is best effort across replicas. A deleted chat/forgotten preference UUID cannot be recreated for 90 days. Conversation context is user/entity scoped and bounded to four completed questions/plans/references, never old amounts as current facts.

## Ledger source and mapping approval

Read ../contracts/ledger.md. Only normalized, balanced, complete posted journals with opening trial balance and explicit cash/accrual basis are accepted. Exact amounts are minor-unit strings. No CSV guessing, currency conversion or real-data import is performed here. A finance owner must supply the export adapter, complete period coverage, account classifications/normal sides, source cutoff, expected totals and sign-off.

Build first. Dry run: node --env-file=.env --import tsx scripts/import-ledger.mts --file /secure/source.json --organisation UUID --actor UUID --entity UUID --expected-version 0. The actor must have scoped import permission. Review digest/mapping fingerprint and expected version; add --apply only for an authorized import. Snapshots are immutable and audit creation is atomic. Configure ASSISTANT_LEDGER_MAPPING_IDS as comma-separated exact mappingId@sha256 approvals from finance review. Fingerprints bind basis/currency/precision/account classifications, not merely a friendly name. An unapproved source exposes raw review data but no derived metrics or Assistant financial answers. Synthetic engineering mappings are not production approval.

Receivables use imported invoice issue-date/cumulative-paid snapshots; they cannot establish historical cash, revenue or aging without supporting dates. Checklist completion is operational, not accounting approval. Saved subscriptions are renewal metadata, not billing. Cross-module cutoffs are disclosed; no invented reconciliation. Pinned ledger/invoice viewers retain original snapshot provenance; checklist/subscription viewers explicitly show current mutable source rows.

## Verification, monitoring and release

Local checks: npm run build, npm test, npm run lint; from root node contracts/validate_assistant.mjs. Frontend test:assistant and test:assistant:production use controlled providers, not paid model proof. node --env-file=.env --import tsx scripts/evaluate-assistant.mts defaults to no requests; missing settings report BLOCKED. --live-synthetic explicitly permits up to two synthetic turns/four actual model calls and requires at least 100000 configured tokens. Run from the checkout; contracts are not copied into the runtime image. This is a smoke evaluation, not sufficient quality approval.

Before release, run representative/adversarial questions against the approved actual model: period cash vs revenue, receivable settlement, customer/account follow-ups, missing dates, ambiguous names, source refresh, cross-tenant requests, injected source labels, secret requests, preferences, refusal/timeouts/rate/credit exhaustion. Record actual model/provider, settings, expected source facts, pass/fail and review owner without private prompts in public artifacts. Current real-model evaluation is blocked by absent approved configuration.

Assign operations/security/finance/billing owners. Alert on readiness failure, pending leases older than 40 seconds, provider failure codes, reservation exhaustion, cleanup backlog, denied source access and failed backup/restore. Use safe status/counters and existing audit metadata; never log credentials or question/source payloads. Dedicated hosted monitoring and alert routing remain external setup, not implemented dashboards.

Before production: verify CI at exact commit, review migrations, configure a staging host/database/session proxy, approved model routing/spend/privacy and finance mapping, run actual-provider/staging tests, test logout/revocation/source refresh and small-screen UX, create encrypted off-host backups and rehearse restore with the actual deployment owner. scripts/restore-rehearsal.sh checks seven migrations and synthetic Assistant/source/auth history locally; it is not proof of off-host production backup. After restore revoke sessions and reconcile deletion retention before reopening access. Roll back by disabling Assistant and deploying the previous application; preserve additive tables/snapshots/audit. Do not drop tables or roll back migration history as an application rollback.

## Vercel and free-model troubleshooting

The Vercel project root is frontend. Its proxy reads only FINAI_BACKEND_ORIGIN, FINAI_PUBLIC_ORIGIN and FINAI_PROXY_TOKEN; placing OPENROUTER_API_KEY only there does not configure the separate Nest backend. Set the Assistant variables on the backend runtime, keep the key server-only, and restart/redeploy that runtime after an authorized configuration change. The production Compose manifest now explicitly forwards all eight Assistant variables from the operator environment. Never print resolved production compose config; it contains secrets.

The user selected free models only. Nonzero price caps are rejected by the adapter, and requests independently pin both price caps to0. For an approved model, set both ASSISTANT_MAX_INPUT_PRICE=0 and ASSISTANT_MAX_OUTPUT_PRICE=0 explicitly, plus the approved exact ASSISTANT_MODEL and provider allowlist. Blank price settings are rejected. This prohibits paid provider routing but does not grant unlimited tokens or guarantee any model is available. OpenRouter free variants have their own quotas/availability; not every model supports required strict structured output or approved privacy routing. Do not enable fallback to paid or unapproved models. No current free-model catalog, actual response compatibility or remaining free quota has been verified here: catalog requests returned403 and no backend key is available. The app deliberately does not display a fabricated OpenRouter token balance.

The demo is /demo/assistant. The main Ask FinAI button and /assistant must open /workspace/assistant, which may require sign-in and configured backend sources. A successful frontend deployment alone cannot establish backend/database/provider readiness. Verify the actual backend's capabilities after authentication, migration status and explicit configured model before evaluating real requests. Never interpret a controlled-provider integration test as proof that all OpenRouter models work.
