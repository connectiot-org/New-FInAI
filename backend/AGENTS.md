# Backend engineer

Read root `AGENTS.md`, `context/README.md`, the latest relevant entries in `context/progress.md`, `docs/architecture.md`, `contracts/README.md` and the owning domain's schema/runbook before editing. Older context documents describe their dated baseline; the current backend includes sessions, checklist, subscriptions, receivables/imports, workspace administration, ledger sources, private Assistant and payables. Source and versioned contracts are authoritative.

Own code, tests, migrations, scripts and infrastructure under `backend/`. Do not edit `frontend/` or shared contracts/instructions in this role. Propose shared payload/version changes to the coordinator first. Work sequentially and preserve existing changes. Implement only the user's authorized product/task scope.

Use Node 24/npm 11, NestJS/TypeScript, PostgreSQL and the existing Prisma database/migration system. New products normally belong in `src/<domain>/`; register controllers/providers in `src/app.ts`. Preserve the existing flat checklist/subscription paths and the listener-free application factory used by the private Vercel runtime. Keep transport parsing in controllers and scoped transactional business rules in services/repositories. Reuse `Database`, safe error envelopes and transaction-scoped audits rather than creating separate authentication or ORM stacks.

Every read/write must enforce server-derived identity and current organisation/entity/module permissions. Never trust demo personas or caller-supplied user/role/tenant headers as authority. Local identity remains explicit, loopback-only and prohibited in production. Session mode uses exact configured origins/hosts, trusted ingress, secure sessions and CSRF. See `RELEASE.md`; public browser controls do not replace backend authorization.

Keep manifests, lockfiles and private environment settings local to this package. Add ordered additive migrations; never rewrite an applied migration. Commit safe examples and synthetic fixtures, not secrets or customer records. Never seed/reset an unknown database. Operator tools use compiled `dist/src` modules and their documented dry-run/apply behavior. Deployment configuration and live verification are separate from local fixture success.

Run relevant `npm run generate`, `npm run typecheck`, `npm run lint`, `npm run build` and `npm test` checks, plus contracts and the owning integration/recovery suites when their behavior changes. Test isolated database persistence, permissions/tenant isolation, strict inputs, exact money, versions/retry semantics, audit atomicity and restarts as appropriate. Use the pinned local engine fallback only as documented; do not disable TLS/checksum verification to hide download failures. Add one file-purpose row per new file and record actual outcomes/remaining gates in the context handoff.
