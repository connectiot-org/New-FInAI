# Assistant 1.0.0

Authenticated private user-owned conversations, fixed entity/month/currency (not demo scope). All queries and JSON bodies strict; UUIDs canonical, Gregorian month, safe no-store/request-ID error envelope inherited. Read permission suffices for personal conversation/preferences; import permission controls trusted ledger import. No financial mutations. Ordinary16KiB request cap unchanged.

GET /assistant/capabilities: configured, model (nullable), policy, ledger mappings enabled (boolean), limits. Never returns credentials. GET /assistant/conversations?entityId&offset=0&limit=20(max50): owned, authorized, nonexpired scope metadata. POST /assistant/conversations {id,entityId,month,currency}: immutable creation digest, identical retry returns original; changed payload409, capacity100. GET /assistant/conversations/:id: owned scope, version, bounded latest50 turns; older turns available GET /:id/turns?offset&limit. DELETE /:id {expectedVersion}: confirmed versioned cascade, safe audit, no resurrection.

POST /assistant/conversations/:id/turns {id,question,expectedVersion}: <=2000 well-formed characters; reserve lease40s and durable daily token budget in short transaction, return202 immediately, background inference outside transactions. Exactly one pending turn/conversation, max2 pending/org, max200 turns/chat. Same request UUID and canonical digest returns original status without inference; changed payload409. GET /:id and /:id/turns expire abandoned leases to failed, never re-run provider. Completed/failed/cancelled terminal; cancellation via DELETE /:id/turns/:turnId {expectedVersion}, session recheck and conditional lease completion. A failure or crash never automatically retries spend; deliberately submit a new UUID after reviewing failed state. Conversation version increments on reserve/cancel; completion uses lease token and conversation presence. Delete/cancel cannot be undone by a late worker.

Turns persist question, status, structured answer facts/citations, source provenance, policy/model, safe failure code, timestamps and original request digest. Historical answers remain dated; new questions retrieve current source. Working context: last4 completed questions/plans, no financial claim is treated as current truth. No private chain-of-thought retained. Model selects allowlisted reads and fact IDs/approved basis notes; exact numerical claims are rendered from server facts, never model numbers or arbitrary links. Up to3 tools,12 answer facts,20 records/tool. Visible scope is immutable; UI explicitly creates another chat for scope changes.

GET /assistant/preferences?entityId returns own active preferences (max1/entity). PUT /assistant/preferences/:id {entityId,detail:concise|detailed,note<=500,expectedVersion:0 for create or current}: explicit save/amend, CAS; concise selects max3 facts, detailed max12. Notes are untrusted optional context, never accounting facts or authority. DELETE /:id {entityId,expectedVersion}: forget confirmation, CAS. History and provider requests/backups have separate lifecycles.

Default retention: conversation30days from creation (fixed, not silently extended), preference365days from explicit save/edit; expiry is enforced on read/use immediately. Trusted cleanup dry-run/apply purges expired chats/turns/preferences; audit retains only UUID/reason/count. Offboarding blocks all reads and inference publication; operator retention process must delete user data per policy. Backups/provider retention separately configured. UUID-only deletion receipts prevent stale create retries for90days; no chat/note content remains in receipts. Cleanup purges expired receipts and budgets older90days. No browser persistence.

Configuration: ASSISTANT_ENABLED=true, server OPENROUTER_API_KEY, explicit ASSISTANT_MODEL, comma-separated ASSISTANT_OPENROUTER_PROVIDERS, ASSISTANT_DAILY_TOKEN_LIMIT (>=50000), ASSISTANT_MAX_INPUT_PRICE and ASSISTANT_MAX_OUTPUT_PRICE (USD/million tokens, explicit). No defaults/fallback models. Provider only approved list, no fallback, require_parameters, data_collection deny, zdr true. Each turn conservatively reserves50000tokens/day/org, no automatic refund; two max1000-output calls, bounded <=16000 UTF8-byte messages each. This is a conservative token allowance, not billing certification; configure provider account spend cap too. Plan/compose deadlines12s each; lease40s; no synchronous long-running HTTP. Provider errors safe codes, no prompts/logging. Missing config is explicit503, not a demo reply.

GET /assistant/source?entityId&month&kind=checklist|subscriptions&offset&limit provides bounded current incomplete tasks or nonarchived renewals for that exact scope. Source citations point to /workspace/assistant/source with those fields. Mutable operational records may differ from historical saved answers; both retrieval timestamps and basis remain visible. No provider call or new financial mutation occurs.


Deployment policy (user-selected, 25 October 2026): OpenRouter free-only routing. Both explicit server price caps must be zero; nonzero/blank settings leave the provider unconfigured. Requests always pin prompt/completion max_price to0 with no fallback. This is a routing constraint, not a guarantee of catalog availability, provider quota or compatibility of every model. HTTP shapes are unchanged.


## Model selection — contract1.1.0

Authenticated GET /api/v1/assistant/models returns ModelList (items id/name, retrievedAt, defaultModel nullable, freeOnly:true). The server fetches only the fixed OpenRouter public catalog, bounds bytes/time/count and caches eligible text models for5 minutes. Eligibility requires zero prompt/completion/request pricing and advertised strict structured_outputs support; it does not guarantee live availability, routing/provider/privacy compatibility or quota. Catalog failures are explicit; no invented catalog or provider output. TurnCreate accepts optional model; existing clients may omit it for the configured default. Nondefault IDs must be in the fresh server catalog. The chosen provider instance is pinned to the reserved turn and persisted via its existing model column; stable UUID/digest retries cannot switch model or repeat spend. Both planning/composition use that instance. No new migration or change to tenant/user/session authorization. All paid/fallback routing stays prohibited.
