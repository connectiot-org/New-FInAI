# Invoice Assistant contract 1.0.0 / Assistant 1.2.0

Coordinator scope: additive supplier-invoice grounding and explicitly confirmed commands. Existing Assistant and payables requests keep their meanings. No model executes a mutation, supplies identity, edits accounting fields, changes policy or pays an invoice.

`Plan.operations` adds `supplier_invoices`, optional nullable `invoiceId`, literal supplier/reference `invoiceSearch`, and `invoiceAction` (default `explain`; otherwise review, verify, approve, correction, challenge, reject, export). Search text must occur in the question or authorized prior labels. IDs must occur in the user's question or authorized bounded prior references. Company/month/currency remain the conversation scope; GBP supplier invoices are separate from USD imported receivables. Summary reads have a 1000-record bound; exact invoice reads remain available. Facts cite current mutable records with version/retrieval time, never a historical ledger balance.

`Answer.proposals` optionally contains up to3 server-built proposals: operationId, invoiceId/entityId, reference, expectedVersion/revision, action, title, description, reasonRequired and sourceId. The model only requests an allowed read/intent; the server computes facts and eligibility. Proposals perform no writes. Old answers without proposals remain valid. AP view authority is checked for retrieval, late publication and reading stored answers.

`POST /api/v1/payables/invoices/{id}/assistant-actions` requires a real authenticated session, CSRF and `{operationId,entityId,expectedVersion,action,reason?}`. Confirmation is explicit in the UI. The server rechecks account, membership, company/AP grant, current assignment, no-self-approval, version, document/policy readiness and reason in existing financial transactions. Identical retries replay; changed payloads conflict. Results are `{kind:transition,id,state,version}` or `{kind:export,id}`. Export downloads use the existing private endpoint. Assistant-channel provenance is recorded with the original business transition; audit failure rolls it back.

The latest public invoice entry and old development URLs open the labelled no-login samples at `/demo/payables/*`. Real company pages remain at `/workspace/payables/*` behind sign-in; no failed production request falls back to samples. FinAI Assistant source links preserve entity and invoice scope. Actual hosting, database migration/account/scanner/provider configuration and live model evaluation are release requirements, not inferred from local controlled-provider tests.
