# Reporting source decision record — proposal, not an implemented API

Proposed first input: vendor-neutral normalized trial balance from the external accounting system of record, reconciled by its finance owner. The invoice register is insufficient. Authorization to continue does not identify an accounting system, confirm export semantics or approve mappings/results.

Required envelope: version, authorized entity mapping, source system/name, currency/decimal precision, period start/end, complete-period flag, accrual/cash basis, capture cutoff/timezone, opening/closing basis and immutable digest. Account rows require stable source account ID/code/name, opening debit/credit, period debits/credits and closing debit/credit as exact decimal strings. Define gross debit/credit versus signed net before freezing a schema. Journal detail needs stable journal/line IDs, posting date/status, account/currency and balanced debit/credit; never infer journals from invoices.

Finance must approve actual export/source ownership, cutoff/completeness, precision/sign conventions, account classifications/mapping version, retained earnings/opening balances, comparative snapshots, materiality and unmapped/contra-account treatment. Independent expected trial-balance/account/P&L/balance-sheet fixtures require real finance approval before claiming accounting correctness. Cash flow requires approved method/movements/classification; consolidation requires FX/elimination policies. These approvals and source exports were not supplied in this session.

Gate: freeze source contract after those decisions; preserve exact raw values and immutable mappings/source versions; reject unbalanced/incomplete/mixed/unsupported input, show missing periods/material unmapped accounts explicitly and trace aggregates to source. Deliver source validation/import → trial balance → account detail → P&L → balance sheet. Existing statements stay demo; this increment exposes no production financial statements.
