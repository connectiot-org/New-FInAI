# Public test chat 1.0.0

This separate stateless API has no financial data access and no account/database prerequisite. Existing authenticated API contracts stay unchanged. POSTs require an exact same-origin Origin; cookies/identity are never forwarded to the provider. Responses are JSON with Cache-Control: no-store.

GET /api/chat/models returns {items:[{id,name}],retrievedAt,configured,freeOnly:true}. The bounded five-minute catalog includes models with text input and text-only output with zero prompt/completion/request price, whether or not they support structured output. Names are plain text. Empty catalog is explicit, not populated with fabricated options. configured indicates a server key is present, not that the provider accepted it.

POST /api/chat/messages accepts {model,messages:[{role:'user'|'assistant',content}]}. Strict fields, 1–11 alternating messages starting/ending with user, at most4000 UTF-16 code units per message and12000 combined, raw body64KiB maximum and five-second raw input deadline. Server rechecks catalog eligibility, pins model and prompt/completion price caps0, performs one bounded provider request (no automatic retries), and returns {selectedModel,model,content}. Server-owned FinAI context is prepended to the first user message to preserve compatibility with models without a system role. It explains that this chat cannot access books, invent company figures or perform actions; it adds a fixed bounded overhead and is not financial grounding or an authorization boundary. The returned model is the actual provider-reported model; routers may resolve another free model. Responses with a positive reported cost are rejected. No secret/SQL/provider error body is returned.

Errors: {code,message,requestId}; 400 malformed JSON, 403 cross-origin, 404 unknown route, 405 wrong method, 408 incomplete input timeout, 422 invalid input/model, 429 local/provider rate limit, 502 invalid provider response, 503 missing key/provider unavailable, 504 provider timeout. Every response has X-Request-Id; error-body IDs match that header and metadata-only request logs. Logs contain IDs, route/method, status/code and duration, never questions, answers, keys, cookies or raw IPs. Safe errors distinguish missing/invalid key, quota, model availability and timeouts. Provider error details are not echoed. A known local Retry-After can disable sending until expiry; no upstream quota reset is invented and no automatic retry occurs. Public controls are per warm function instance (5 calls/IP/minute,20 calls/minute total,2 in flight) and do not constitute a durable account-wide budget. OpenRouter key/account quota remains authoritative across instances. No paid routing is allowed.

Provider HTTP401 reports invalid authentication; HTTP403 reports access denied for the selected model or request, without asserting that the server key is invalid. Both use safe503 responses with distinct codes and no upstream body. A model-specific denial does not trigger a fallback or a paid request.

The browser keeps only current-page messages, sends bounded recent history, displays real failures, and never saves conversations to localStorage/sessionStorage. Clearing or leaving removes local state. Messages are sent to OpenRouter/its model provider, whose retention policies still apply. This is general model testing, not grounded financial reporting. Schema examples/bounds: public-chat.schema.json; run node contracts/validate_public_chat.mjs.
