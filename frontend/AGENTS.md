# Frontend integrator

Read root `AGENTS.md`, `context/README.md`, the latest relevant `context/progress.md` entries, `context/agent-boundaries.md`, `docs/architecture.md` and the owning shared contracts before editing. Own browser/API-adapter code, tests and tooling under `frontend/`; backend and shared contracts/instructions belong to their respective roles. Work sequentially and preserve existing changes.

Use Node 24/npm 11 and the package's existing React/Vite/TypeScript stack. New products normally belong in `src/features/<domain>/`. Register company routes beneath the existing `/workspace` router parent and add authorised navigation in `features/workspace/Workspace.tsx`. Use validated workspace context, shared session/transport helpers and explicit feature schemas. Do not copy a whole product into another feature or create a second authentication/state system for convenience.

Keep all three boundaries distinct: original Northstar demo state (`finai-demo-v1`), labelled public invoice samples (`finai-invoices-development-v1`) and authenticated server company data. Public stateless model chat is separate from the grounded private Assistant. Public personas are never authentication. Real API/configuration failures must stay visible and must not fall back to fixtures. Preserve existing demo workflows, source provenance, compatibility redirects and bookmarks; `/workspace/checklist` is the current company checklist entry, while older standalone routes retain their documented modes.

`src/` is browser-safe code. `api/` and `server/` are server-only Node adapters; `.finai-server/` is generated private backend output. Never import Node, Prisma, server settings, test fixtures or private runtime modules into browser source. `VITE_` settings are public and cannot contain credentials. Respect identity epochs, obsolete-request cancellation, pending-write guards and explicit confirmed Assistant actions. Verify loading, empty, error, permission, conflict, refresh and changed-scope/account behavior for actual feature changes.

Run `npm run check:repository`, `npm run test:repository`, `npm run typecheck`, `npm run lint`, `npm run build` and the relevant browser/runtime suites. Typecheck covers all Playwright configurations plus separate NodeNext adapter checks. Playwright uses system Chromium when installed. Browser suites share ports/artifacts and must run sequentially; choose the owning configuration for each new spec and update exclusions/CI when necessary. Do not format unrelated files or rewrite generated lockfiles/schemas by hand. Add each new file to the purpose catalog and record real outcomes in the context handoff.
