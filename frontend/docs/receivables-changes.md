# Import Change Review

In the authenticated invoice register, choose **Compare imports** next to source history. The private route is `/workspace/receivables/changes`. Read-only entity members can use it; import/write grants are not required. The existing database, migrations and legitimate saved imports are prerequisites. No new table, migration, key or model service is needed.

The latest two versions are selected initially and their entity/source IDs are pinned in the URL. With one source, both sides default to that source and the page explains the zero-change result. Browse older source choices to load further history pages. Choose earlier/later imports, then compare explicitly; changing a selection hides the prior result. Reloading source choices or importing a third source does not replace a pinned comparison. Source links open the existing all-issue-date/all-status pinned register, where the displayed invoice ID can be located.

All invoice IDs and source statuses are included. A non-Draft row contributes amount minus cumulative paid, otherwise zero; fully paid and absent rows also contribute zero. Absence remains a null record, not a fabricated source row. Totals and the four-part bridge cover the complete union before changed-only pagination. New money strings are formatted with BigInt, including values above Number.MAX_SAFE_INTEGER. Source fields, overlapping factual labels and a distinct changed-invoice count are shown. A backward source cutoff has a caution. No cash receipt date, write-off, deletion, aging or accounting reason is inferred.

Errors, forbidden/unconfigured services and network failures stay visible without demo fallback. Entity/source/session transitions cancel or ignore stale reads; no comparison or source register is saved in browser storage. The comparison module is loaded only for this private route; global branding and demo state stay independent.

From `frontend/`: `npm run typecheck`, `npm run lint`, `npm run build`, `npm run test:workspace` (includes comparison states/schema/format/pagination/races), and `npm run test:workspace:production` (builds then uses real synthetic PostgreSQL, HTTPS session/proxy/API). Backend must be built and its local test database running first. Existing scripts now discover the new tests; no new package script or dependency was added. The built journey covers the255000→215000 example, source links/cutoff, third-import stability, restart, expiry and1440/768/390/320px keyboard/scroll containment. Ignored screenshots are under `frontend/artifacts/import-changes/`.
